# Видео по скроллу для Tilda

121 кадр 1280×720, JPEG q95 — 16.1 МБ (из 105 МБ исходных PNG).
Отрисовка через `<canvas>`, кадр привязан к прогрессу скролла.

## Что в папке

| Файл | Назначение |
|---|---|
| `frames/` | 121 кадр `frame_0001.jpg … frame_0121.jpg` |
| `preview.html` | локальная проверка — **открой двойным кликом** |
| `tilda-block.html` | то, что вставляется в Tilda (блок T123) |
| `server.ps1` | статический сервер, если захочешь проверить по http |

---

## Шаг 1. Проверить локально

Открой `preview.html` двойным кликом и покрути колесо. Эффект должен идти
плавно, внизу — полоска загрузки.

## Шаг 2. Выложить кадры на GitHub + jsDelivr

jsDelivr бесплатно раздаёт любой публичный GitHub-репозиторий через
глобальный CDN. URL получаются предсказуемые — это важно, код просто
подставляет номер кадра.

1. Создай на GitHub **публичный** репозиторий, например `scroll-frames`.
2. В этой папке выполни:

   ```bash
   git init
   git add frames
   git commit -m "121 frame for scroll animation"
   git branch -M main
   git remote add origin https://github.com/USER/scroll-frames.git
   git push -u origin main
   ```

3. Поставь тег — чтобы jsDelivr кешировал версию навсегда и ссылки не
   «поехали», если потом что-то перезальёшь:

   ```bash
   git tag v1
   git push origin v1
   ```

4. Проверь, что кадр открывается в браузере:

   ```
   https://cdn.jsdelivr.net/gh/USER/scroll-frames@v1/frames/frame_0001.jpg
   ```

> Репозиторий обязан быть **публичным** — jsDelivr не умеет читать приватные.
> Первое обращение к новому тегу может занять несколько секунд, дальше отдача
> идёт с ближайшего edge-узла.

## Шаг 3. Вставить в Tilda

1. На странице добавь блок **T123** (Другое → HTML-код).
2. Вставь всё содержимое `tilda-block.html`.
3. В начале `<script>` замени `USER` и `REPO` на свои:

   ```js
   base: 'https://cdn.jsdelivr.net/gh/ivanov/scroll-frames@v1/frames/',
   ```

4. Опубликуй страницу. **Внутри редактора Tilda эффект не работает** —
   смотри только на опубликованной странице или в режиме просмотра.

## Настройки

Всё в объекте `CFG` в начале скрипта:

| Параметр | По умолчанию | Что делает |
|---|---|---|
| `scrollHeight` | `400` | «Длина» ролика в vh. 400 = 4 экрана прокрутки на 121 кадр. Больше — медленнее и детальнее |
| `smoothing` | `0.18` | Плавность догона кадра. `0` — жёстко привязано к скроллу, `0.3` — заметная инерция |
| `count` | `121` | Число кадров |
| `concurrency` | `8` | Сколько кадров грузится параллельно |

## Как это устроено

* Контейнер высотой `scrollHeight` vh, внутри `position: sticky` — картинка
  «залипает» на весь экран, пока страница прокручивается мимо.
* Прогресс прокрутки контейнера → дробный номер кадра. Между текущим и
  целевым кадром идёт интерполяция в `requestAnimationFrame`.
* Кадры грузятся очередью по 8 штук. Пока нужный кадр не готов, рисуется
  **ближайший загруженный** — поэтому при быстром скролле нет чёрных провалов.
* Канвас масштабируется под `devicePixelRatio` (с потолком ×2) и рисует
  кадр по логике `object-fit: cover`.
* Tilda часто вешает `overflow: hidden` на блок-обёртку, что ломает
  `sticky` — скрипт при старте проходит вверх по родителям и снимает это.

## Если что-то не так

**Картинка не «залипает», просто проезжает мимо.** Какой-то родитель всё
ещё с `overflow: hidden`. Проверь в DevTools цепочку над `.sfx`.

**Долго грузится на мобильном.** Уменьши `scrollHeight` или пересобери
кадры в WebP — при том же качестве выйдет примерно вдвое легче (~9 МБ),
нужен `ffmpeg`.

**Кадры не находятся (404).** Репозиторий приватный, не создан тег `v1`,
или в `base` опечатка. Открой ссылку из шага 2.4 напрямую в браузере.
